# มาตรฐานการสร้างร้อยแก้ว Dust & Fire: Sengoku Stories

**สถานะ:** มาตรฐาน runtime อย่างเป็นทางการใน working branch ณ 27 สิงหาคม 2026  
**ขอบเขต:** ใช้กับข้อความ AI GM ทุก field ที่ผู้เล่นเห็น ได้แก่ ชื่อฉาก ร้อยแก้วสามย่อหน้า ทางเลือก ความทรงจำ และโน้ตภารกิจ  
**หลักสูงสุด:** ผลของเกมถูกตัดสินโดย deterministic engine ก่อนเสมอ ร้อยแก้วมีหน้าที่ตีความผลที่ถูกล็อกแล้วเท่านั้น

## 1. จุดประสงค์

ระบบนี้ไม่ได้พยายามให้โมเดล “เขียนเก่งเอง” แต่กำหนดให้โมเดลหลายค่ายเขียนในกรอบเดียวกัน โดยมีคีย์หลักจากงานของเจ้าของโครงการเป็นศูนย์กลาง ข้อเท็จจริงของฉากและผลของกติกามาก่อนเสียงภาษาเสมอ หากไม่มีหลักฐานรองรับ ระบบต้องเขียนเป็น campaign fiction ที่มีขอบเขต ไม่แต่งเหตุการณ์ทางประวัติศาสตร์ให้ดูเหมือนเรื่องจริง

## 2. สายการทำงานขณะเล่น

| ขั้น | เจ้าของการตัดสิน | สิ่งที่ส่งต่อ | เวลารอของผู้เล่น |
|---|---|---|---|
| 1. Resolve | deterministic engine | ผลสำเร็จ/ราคา/ผลกระทบที่เปลี่ยน state | ไม่มี AI |
| 2. Scene Brief | server | ปี สถานที่ ฤดู สถานะตัวละคร ฉาก ผลที่ล็อก และ historical brief ที่อนุญาต | โค้ดในเครื่อง |
| 3. Retrieval | server | Golden Example ที่เกี่ยวข้องสูงสุดไม่เกิน 2 ชิ้น | โค้ดในเครื่อง |
| 4. Narrative Packet | server | Style Bible + invariants + ตัวอย่าง + JSON schema | รวมอยู่ในการเรียก AI ครั้งเดียว |
| 5. Draft | LLM | JSON ที่มีร้อยแก้ว 3 ย่อหน้าและทางเลือก 3 ทาง | จุดที่ใช้เวลาหลัก |
| 6. Gate | server | ตรวจยุคสมัย ภาษาเกม ข้อมูลลับ ภาษาไทย และโครงสร้าง | โค้ดในเครื่อง |
| 7. Recovery | server/client | retry 1 ครั้ง หรือ deterministic local fallback | เกิดเฉพาะเมื่อ draft ไม่ผ่าน |

ตัวอย่างและ Style Bible ถูกส่งใน **การเรียกเดียว** กับการสร้างร้อยแก้ว จึงไม่เพิ่มจำนวนรอบรอปกติ การให้ AI judge เต็มรูปแบบเป็นงาน QA นอกช่วงเล่น ไม่อยู่บน critical path ของผู้เล่น

## 3. คีย์หลักที่สกัดจาก corpus ของเจ้าของ

นิยายบทที่ 1–5.1 กำหนดมาตรฐานภาษาไทยของ Dust & Fire ไว้ดังนี้

| คีย์ | วิธีใช้ในร้อยแก้ว |
|---|---|
| วัตถุมีน้ำหนัก | ฝน ควัน ไม้ เชือก เกลือ หมึก ดินปืน คราบเลือด และอาวุธต้องส่งผลต่อท่าทาง ไม่ใช่รายการตกแต่งฉาก |
| ร่างกายไม่โกหก | แผล ความล้า เมาเรือ และแรงถอยหลังของปืนปรากฏผ่านการเดิน จับ หายใจ และการตัดสินใจ หาก state ระบุไว้ |
| อำนาจเห็นได้ | ฐานะปรากฏจากคนใครยืน/นั่ง ผู้ใดมีสิทธิ์สั่ง ผู้ใดต้องกลัวการถูกเห็น และคำพูดใดมีผลตามมา |
| บทสนทนากดทับ | ผู้มีอำนาจไม่จำเป็นต้องตะโกน; ประโยคสั้นและเงื่อนไขชัดย่อมสร้างแรงกดดันได้มากกว่า |
| ความลับคือพฤติกรรม | การชำเลืองประตู ลดเสียง เลื่อนมือจากของ หรือเลือกไม่ตอบ บอกความลับได้โดยไม่เปิดเจตนาลับของ NPC |
| ผลไม่ฟรี | ความสำเร็จและความพลาดต้องทิ้งชื่อ หนี้ พยาน ข่าวลือ ความไว้ใจ หรือภาระที่จับต้องได้ |

Golden Example ของเจ้าของมีสิทธิ์เหนือกว่า foundation example และถูกใช้เพียงเพื่อสอนจังหวะ วิธีเห็นภาพ และการรับน้ำหนักของบทพูด ระบบห้ามนำชื่อ ฟูยุ ซาเนฟุยุ คูกิ กันทาโร่ หรือเหตุการณ์เดิมไปคัดลอกสร้างเป็นฉากใหม่

## 4. รีเซิทภาษาและยุคสมัย

### ไทย

ใช้ภาษาไทยกลางร่วมสมัยในฐานะ “ภาษานิยายที่เล่าโลกเซนโกคุ” ไม่แกล้งเป็นภาษาไทยโบราณ ไม่แปลญี่ปุ่นคำต่อคำ และไม่ใช้ภาษาระบบ บทพูดต้องติดกับกิริยาและฐานะ; โรนินพูดตรงได้ ผู้คุมควบคุมจังหวะ พ่อค้าชั่งเงื่อนไข ช่างสนใจวัสดุ และชาวบ้านผูกคำพูดกับงาน ครอบครัว หรือความปลอดภัย

### ญี่ปุ่นและหลักฐาน

ความแท้ของฉากไม่ได้มาจากการโรยคำญี่ปุ่นหรือสมมติพิธีการเฉพาะถิ่น แต่จากวัสดุ สถานะ ความรู้ที่ตัวละครเข้าถึง และเหตุการณ์ที่มีหลักฐาน งานจดหมายญี่ปุ่นศตวรรษที่ 16 ควรอ่านพร้อมรูปแบบพู่กัน ผู้ส่ง ผู้รับ สถานที่ และเรื่องราวของวัตถุ ไม่ใช่เพียงถอดเนื้อความ [1] ส่วนเคียวเง็นเป็นหลักฐานสำคัญเพื่อศึกษาภาษาพูดในช่วงมุโรมาจิถึงเอโดะ [2] แต่ไม่ใช่ใบอนุญาตให้ยกบทละครหรือคำขบขันลงทุกฉากชีวิตประจำวัน

### อังกฤษ

English output ใช้ **modern literary historical English**: แม่น ชัด คุมจังหวะ และยึดรายละเอียดวัตถุ ห้าม faux-archaic เช่น *thee/thou*, ห้ามสำนวนแฟนตาซี และห้ามคาล์กภาษาไทย เป้าหมายไม่ใช่ให้คนญี่ปุ่น ค.ศ. 1569 พูดภาษาอังกฤษร่วมสมัยจริง แต่คือถ่ายทอดเหตุการณ์ ระยะอำนาจ และขอบเขตความรู้เดียวกับไทยอย่างอ่านลื่น

## 5. กติกาห้ามละเมิด

ข้อความผู้เล่นห้ามมีผลทอย, DN, Trait, Mastery, โบนัส, AI, prompt, card/brief, การวิเคราะห์ภายใน หรือข้อมูลจาก private dossier ห้ามมีวัตถุ/ถ้อยคำสมัยใหม่ที่ตัวกรองระบุ เช่น ปากกา ปากกาลูกลื่น คลิก โทรศัพท์ รถยนต์ ไฟฟ้า เจ้าหน้าที่ ตำรวจ ออฟฟิศ โปรไฟล์ และระบบ

ตัวกรองเป็น **hard fail** ไม่ใช่คำแนะนำ ถ้าพบการละเมิด โมเดลถูกสั่งให้เขียนใหม่หนึ่งครั้ง; ถ้ายังไม่ผ่าน เกมใช้ local deterministic prose แทน และไม่ render ร่างที่ถูกปฏิเสธ

## 6. Golden Example intake และการขยาย library

เจ้าของส่งนิยายได้ทั้งบทโดยไม่ต้องติด tag ระบบอ่านภาพรวมก่อนคัดเฉพาะย่อหน้าที่เป็นตัวแทนเสียงงาน แล้วติด tag ภายใน เช่น `ronin`, `authority`, `merchant`, `document`, `water`, `war`, `injury`, `secrecy`, `craft`, `pressure` และ `consequence` หนึ่งตัวอย่างควรสอนเรื่องเดียวเด่น ๆ และยาวพอให้เห็นจังหวะ แต่ไม่จำเป็นต้องเก็บทั้งบท

ก่อนรับเข้า `user-approved` ตัวอย่างต้องผ่าน 4 ข้อ: ไม่มี artifact เกม, ไม่มีรายละเอียดร่วมสมัย, ไม่เปิดข้อมูลลับที่ผู้เล่นไม่ควรรู้ และไม่ถูกยกเป็นหลักฐานประวัติศาสตร์นอกบริบทต้นฉบับ หากรายละเอียดเวลา/สถานที่ไม่ชัด ตัวอย่างยังใช้สอนภาษาได้ แต่ใช้ยืนยันข้อเท็จจริงของฉากอื่นไม่ได้

## 7. การประเมินและการ promote

candidate ใหม่จะเข้าทางหลักได้ก็ต่อเมื่อไม่มี hard fail และคะแนน deterministic rubric สูงกว่า baseline ที่อนุมัติแล้ว คะแนนพิจารณา 4 มิติ: ร้อยแก้ว, ยุคสมัย, โครงสร้าง และความต่อเนื่องของทางเลือก การประเมินเชิงรสนิยมละเอียดควรใช้ AI judge หรือ human review นอกช่วงเล่น เพื่อไม่เพิ่ม latency และต้องไม่ให้โมเดลผู้เขียนตัดสินงานของตัวเอง

## 8. ขอบเขตที่ยังต้องยืนยันกับเจ้าของ

ตัวอย่างที่คัดจาก corpus เป็นการสกัดเบื้องต้น ไม่ใช่คำประกาศว่าทุกประโยคคือกฎตายตัว เจ้าของควร review log ตัวอย่างสองชุดก่อน แล้วชี้ว่าอะไร “ใช่”, “เกิน”, หรือ “ยังไม่ใช่” เพื่อเปลี่ยนจาก sample library เป็นคีย์หลักที่แม่นยำยิ่งขึ้น
