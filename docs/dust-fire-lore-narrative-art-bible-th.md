## 1. หน้าที่ของเอกสารนี้

เอกสารฉบับนี้ไม่ใช่ chronicle ที่บังคับผู้เล่นให้เดินตามเส้นเดียว แต่เป็น **กฎสำหรับทำให้ทุกเรื่องที่เกิดจากการเล่นรู้สึกว่าอยู่ในโลกเดียวกัน**. AI GM ใช้เพื่อเขียนฉากและเลือกน้ำหนักทางสังคม; ระบบหลังบ้านใช้เพื่อ validate คำตอบและป้องกันข้อเท็จจริงเทียม; ทีมอาร์ตใช้เพื่อรักษาภาษาภาพ; และทีม UI ใช้เพื่อทำให้กลไกมองเห็นได้โดยไม่ทำลายความเป็นนิยาย.

| คำถาม | คำตอบของ Dust & Fire |
|---|---|
| เกมนี้เล่าเรื่องใคร | คนที่ต้องต่อรองกับสงคราม ไม่ใช่เพียงแม่ทัพที่ชนะสงคราม |
| ผู้เล่นมีอำนาจแบบใด | เลือกวิธี พันธมิตร ราคา และคนที่ถูกทิ้งไว้—not guaranteed victory |
| ความเก่งมีความหมายอย่างไร | ความชำนาญทำให้ทำงานยากได้ดีขึ้น แต่ไม่ลบอำนาจ เวลา พยาน บาดแผล หรือผลประโยชน์ |
| ประวัติศาสตร์อยู่ตรงไหน | เป็นกรอบของความเป็นไปได้ ไม่ใช่เครื่องประดับหรือ quest database |
| แกนอารมณ์คืออะไร | เกียรติที่ถูกใช้ต่อรอง, บ้านที่ถูกบีบ, ความทรงจำที่ไม่ยอมตาย, และความสำเร็จที่สร้างหนี้ใหม่ |

## 2. เสาหลักของเรื่อง

### 2.1 ธีมที่ต้องอยู่ในทุกแคมเปญ

| ธีม | คำถามเชิงเรื่อง | ตัวอย่างผลที่ควรเกิด |
|---|---|---|
| **เกียรติเป็นหลักทรัพย์** | ใครยอมเชื่อคำเจ้า และใครใช้ชื่อเจ้ามาค้ำสิ่งใด | ได้สิทธิ์ผ่านทาง แต่ชื่อถูกผูกกับคนออกหนังสือ |
| **บ้านไม่ใช่ที่ปลอดภัยเสมอไป** | บ้านต้องการอะไรเพื่ออยู่รอด และใครถูกกันออกจากคำว่า “เรา” | เสบียงพออยู่ต่อ แต่แรงงานในบ้านแตกฝ่าย |
| **อำนาจต้องมีคนทำงานให้** | คำสั่งของผู้ใหญ่เดินทางผ่านมือใครบ้าง | ทหารไม่ได้มาถึงก่อน แต่คนเก็บภาษีและคนหาเรือมาถึงก่อน |
| **ความทรงจำมีตัวตน** | ใครเห็น ใครถือสำเนา ใครได้ยินคำสาบาน | ความลับไม่หลุดทันที แต่มีพยานคนหนึ่งจำได้ |
| **ความรุนแรงมีงานธุรการ** | ใครขนเสบียง ซ่อมอาวุธ จดรายชื่อคนหาย และฝังศพ | ฉากสงครามเริ่มจากบัญชีข้าวหรือทางเกวียนที่ถูกปิด |
| **ความเมตตาอาจเป็นหนี้** | การช่วยคนวันนี้เปิดหรือปิดทางใดพรุ่งนี้ | ได้คนช่วยรักษาแผล แต่ครอบครัวเขารอการตอบแทน |

### 2.2 ความขัดแย้งหลัก

เรื่องที่ดีของ Dust & Fire ควรมีอย่างน้อยสองแรงดึงที่ไม่แก้ด้วยการทอยครั้งเดียว เช่น ความปลอดภัยปะทะความจริง, ครอบครัวปะทะคำสัตย์, เส้นทางค้าขายปะทะการเมือง, ความเป็นกลางปะทะการเอาตัวรอด หรือชื่อเสียงปะทะชีวิตของคนที่ไม่มีชื่อ.

> ห้ามวางโจทย์ว่า “คนดีชนะคนชั่ว” โดยไม่มีราคา. ให้ถามว่า “ใครจะต้องรับภาระ เพื่อให้สิ่งที่ดีที่สุดที่ทำได้ยังคงอยู่?”

## 3. การตั้งค่าของโลก: โลกเซ็นโกคุที่ไม่ลดเป็นภาพจำ

### 3.1 กรอบเวลาและสถานที่

เกมเปิดใช้ได้ในช่วงปลายมุโรมาจิถึงการรวมอำนาจของญี่ปุ่น แต่แต่ละแคมเปญต้องประกาศ **ปี ฤดู ภูมิภาค เครือข่ายอำนาจ และแรงกดดันสาธารณะ** ก่อนเริ่ม. ชื่อบุคคลหรือเหตุการณ์จริงใช้ได้เฉพาะเมื่อมี fact card ที่ผ่านปีและภูมิภาค; เรื่องของผู้เล่นเป็น campaign fiction โดยค่าเริ่มต้น.

| ชั้นของ setting | ต้องมี | ตัวอย่างที่ถูกต้อง |
|---|---|---|
| **ภูมิศาสตร์** | ทางน้ำ ทางบก สะพาน ตลาด ป่า เนิน ด่าน หรือท่า | “เส้นทางเลียบคิโนะกาวะถูกตรวจ” ไม่ใช่ “ทั่วแคว้นสงบ” |
| **ฤดูกาล** | งานเก็บเกี่ยว น้ำ ฝน ลม ความหนาว หรือโรค | ฤดูเปลี่ยนราคา เวลาเดินทาง และแรงงาน |
| **สถาบัน** | บ้านเรือน วัด เครือญาติ บ้านใหญ่ ผู้ค้ำ พ่อค้า หรือกองกำลัง | ระบุว่าใครดูแลคลัง ใครถือเอกสาร ใครให้ที่พัก |
| **ความกดดัน** | เสบียง ข่าวลือ หนี้ คนหาย คำสั่ง หรือการตรวจ | ให้เห็นคนที่ได้รับผล ไม่เพียงชื่อสงคราม |
| **สิ่งที่ไม่รู้** | ข่าวที่ยังไม่ยืนยัน รอยเท้า เอกสารขาดหน้า | สร้าง agency โดยไม่ปิดคำตอบตั้งแต่แรก |

### 3.2 สังคมไม่ใช่บันไดสี่ชนชั้น

ห้ามใช้กรอบ “ซามูไร–ชาวนา–ช่าง–พ่อค้า” แบบยุคเอโดะเป็นเมนูสถานะตายตัว. ในฉาก ให้ระบุคนผ่านงาน หน้าที่ การคุ้มครอง เครือญาติ ที่ดิน สิทธิ์ทางผ่าน ศาสนา ความรู้หนังสือ หรือผู้รับรอง แทนการสรุปว่าใคร “สูงกว่า” เสมอ [1].

| เขียนแบบอ่อน | เขียนแบบ Dust & Fire |
|---|---|
| “ชาวบ้านไม่มีสิทธิ์พูด” | “ผู้ใหญ่บ้านไม่กล้าพูดต่อหน้าคนเก็บภาษี แต่หญิงที่ดูแลคลังข้าวยังถือกุญแจอยู่” |
| “ซามูไรสั่ง ทุกคนเชื่อฟัง” | “คำสั่งมาถึง แต่คนที่ต้องหาเรือ คนที่ต้องยกข้าว และผู้ค้ำเส้นทางยังต้องถูกโน้มน้าว” |
| “วัดช่วยชาวบ้าน” | “วัดมีคลัง คนเขียนหนังสือ และผู้ลี้ภัย; ทุกทางเลือกจึงกระทบผู้ถือครองและผู้พึ่งพา” |

### 3.3 เศรษฐกิจและการเดินทาง

ตลาดเป็นเครือข่ายของคน สิทธิ์ผ่านทาง ผู้ค้ำ ผู้ตรวจ ของที่ขาด และข่าว ไม่ใช่ร้านค้าที่มี inventory สุ่ม. สิ่งที่ใช้จ่ายได้อาจเป็นเหรียญ ข้าว ของใช้ เอกสารรับรอง แรงงาน ความเงียบ หรือการรับปาก. การแลกเปลี่ยนที่สำคัญต้องตอบว่าใครเป็นพยานและใครยังติดค้าง.

> รางวัลที่ดีที่สุดมักไม่ใช่เงินก้อน: มันอาจเป็นใบผ่าน, ผู้รู้เส้นทาง, ที่พักหนึ่งคืน, ผู้ค้ำประกัน, ยารักษา, สำเนาบัญชี หรือสิทธิ์ให้คนหนึ่งคนได้พูด.

### 3.4 ศาสนาและเครือข่ายท้องถิ่น

วัด กลุ่มศรัทธา ผู้นำท้องถิ่น และเครือข่ายอิกโกะต้องไม่ถูกเขียนเป็นกลุ่มเดียวที่คิดเหมือนกัน. ฉากศาสนาต้องถามว่าใครคุมที่ดิน ข้าว บันทึก ผู้ลี้ภัย ความคุ้มครอง และการไกล่เกลี่ยก่อน [2]. อย่าใช้คำว่า “กบฏชาวนา” เป็นคำตอบครอบจักรวาลสำหรับ Ikkō-ikki.

### 3.5 ภัยพิบัติ ฤดูกาล และโรค

ใช้ความหนาว ฝน ถนนขาด ราคาอาหาร แผลติดเชื้อ แรงงานหาย และข่าวลือเป็นแรงกดดันได้ แต่ห้ามสุ่มชื่อภัยพิบัติจริง. ข้อมูลภัยพิบัติยุคกลางต้องผูกกับแหล่ง ปี และพื้นที่ พร้อมระวังธรรมชาติของหลักฐาน [3].

## 4. แคมเปญและโครงสร้างเรื่อง

### 4.1 หน่วยเรื่อง

| หน่วย | ความยาวในโลก | หน้าที่ |
|---|---|---|
| **Beat** | การกระทำหนึ่งผล | เปลี่ยนแรงกดดันหรือเปิดข้อมูล |
| **Scene** | ช่วงสนทนา การเดินทาง งาน หรือ confrontation | ให้ผู้เล่นตัดสินใจหนึ่งเรื่องสำคัญ |
| **Leaf** | ราวหลายวันหรือการเปลี่ยนความสัมพันธ์/สถานที่ครั้งใหญ่ | ปิดช่วงเรื่องและเก็บผลไว้ใน Chronicle |
| **Thread** | งานหรือความขัดแย้งต่อเนื่อง | เชื่อมหลาย scene โดยไม่บังคับให้กดรับเควส |
| **Arc** | การเปลี่ยนคำตอบของตัวละครต่อธีม | ทำให้ชื่อ บ้าน วิธีการ หรือความสัมพันธ์เปลี่ยนความหมาย |

### 4.2 โครง Arc ที่ใช้ได้ แต่ไม่บังคับเส้นเดียว

| Arc | จุดเริ่ม | จุดแตกหัก | ปลายเปิดที่เหมาะ |
|---|---|---|---|
| **Ash at the Gate / เถ้าหน้าด่าน** | คนธรรมดาถูกด่านและเอกสารกดทับ | ต้องเลือกระหว่างส่งคนให้รอดกับบอกความจริง | ได้ทางผ่าน แต่ชื่อถูกจด |
| **Winter Name / นามจากหิมะ** | ตัวละครยังไม่มีชื่อที่คนจดจำ | การรบหรือการช่วยชีวิตกลางฤดูหนาว | ได้ชื่อ “ซาเนฟุยุ” หรือชื่อจากการกระทำ ไม่ใช่จาก script ตายตัว |
| **The Price of Protection / ราคาของความคุ้มครอง** | มีผู้เสนออุปถัมภ์ | ผู้คุ้มครองให้สิ่งที่ต้องแลกด้วยคนอื่น | รับอำนาจ, หลบหนี, หรือสร้างทางที่สาม |
| **A House Divided / บ้านที่พูดคนละเสียง** | บ้าน/ชุมชนยังรวมตัว | ความลับ หนี้ หรือเสบียงทำให้คนแบ่งฝ่าย | ความสัมพันธ์เปลี่ยน ไม่ใช่เพียง quest complete |
| **Cinders of Rule / เถ้าของผู้ปกครอง** | ผู้เล่นมีชื่อเสียงหรือทรัพยากร | วิธีที่ใช้เพื่ออยู่รอดย้อนมาทวง | เป็นผู้นำ, หายไปจากโลก, หรือเหลือเพียงชื่อใน Chronicle |

**ข้อสำคัญ:** Arc เหล่านี้คือ palette. ห้ามบังคับว่าผู้เล่นต้องกลายเป็นโชกุน, มีครอบครัว, ถูกทิ้ง หรือเสียชีวิตลำพัง. ระบบต้องเปิดให้เรื่องนั้นเกิดได้เมื่อ state และการเลือกพาไป—not because a prophecy requires it.

### 4.3 สูตรฉาก

ทุก scene ใช้สมการเชิงเรื่องนี้:

```text
Place + Public Pressure + Person with a Want + Hidden Cost + Playable Question
```

ตัวอย่าง:

> **ท่าเรือยามฝน:** เรือข้าวยังไม่ออกเพราะคนตรวจเรือรอหนังสือรับรอง. พ่อค้าอยากให้ของขึ้นเรือก่อนข่าวรั่ว. คนเขียนหนังสือมีสำเนาอีกฉบับซึ่งอาจพาตัวเองตายได้. ผู้เล่นจะช่วยใคร โดยยอมให้ใครเห็นชื่อบนกระดาษ?

## 5. สกิลและความหมายในโลก

### 5.1 หลักการของ skill

สกิลในเกมเรียกว่า **Mastery / Discipline / วิชาที่ฝึก**. มันไม่ใช่ list ให้ผู้เล่นเลือกเพื่อบังคับผล แต่เป็นหลักฐานว่าตัวละครเคยเรียน เคยทำ เคยรอด หรือมีเครือข่ายใดรองรับ. ทุก mastery ต้องมี origin, tags, วิธีที่คนอื่นมอง, ราคาเมื่อใช้ และ Step/XP ของตนเอง.

### 5.2 แกนห้าแกนและตระกูลวิชา

| Axis | คำไทย | คำถามที่ axis ตอบ | ตัวอย่าง mastery | ภาษาที่ควรใช้ในการบรรยาย |
|---|---|---|---|---|
| Prowess | พละกำลัง | ร่างกายทน ทำ หรือพาคนผ่านได้อย่างไร | River crossing, Carrying wounded, Grappling | น้ำหนัก หายใจ กล้ามเนื้อ พื้นลื่น แผล |
| Craft | ฝีมือ | มือ เครื่องมือ และจังหวะทำให้งานสำเร็จได้อย่างไร | Matchlock repair, Seal work, Blade work, Carpentry | เศษโลหะ รอยคม กลิ่นน้ำมัน ข้อต่อ ไฟ |

## 6. กลไกเกมที่ต้องแปลงเป็นร้อยแก้ว

### 6.1 หลัก “กลไกอยู่ใต้ผิวเรื่อง”

ผู้เล่นเห็น total, DN, outcome, Mastery Progress, time mark และ mission result ใน **Result Ledger** หลัง roll; แต่ prose ห้ามพูดว่า “ได้ +1 Progress”, “DN 18”, “partial success” หรือ “AI เลือก Craft”. ให้แปลงกลไกเป็นผลที่จับต้องได้.

| กลไก | UI บอก | Prose ต้องแสดง |
|---|---|---|
| decisive success | total / DN และ outcome | วิธีทำงานจริง, คนเห็นความสามารถ, ทางเปิดใหม่ |
| success with cost | success + cost | ได้สิ่งที่ต้องการ แต่มีเงื่อนไข/พยาน/ของที่เสีย |
| partial success | ได้บางส่วน | เวลา/ข้อมูล/ตำแหน่งที่ยังไม่มั่นคง |
| failure with consequence | ทางเดิมพัง | ความเข้าใจผิด การตรวจ แผล ชื่อเสีย หรือทางเลือกใหม่ |
| Step gained | skill ledger | ตัวละครสังเกตรอยมือ วิธีคิด หรือคนอื่นยอมรับความเปลี่ยนแปลง |
| time mark | clock | แสง กลิ่น อุณหภูมิ งานในตลาด หรือความเหนื่อยเปลี่ยน |
| Leaf close | chronicle | ผลหลายวันถูกสรุปเป็นความทรงจำ ไม่ใช่ cutscene ที่ตัด agency |
| mission resolved | dossier + reward | ผู้มอบงานตอบสนอง, reward มีที่มา, ข้อตกลงถูกบันทึก |

### 6.2 กฎการให้ XP เชิงเรื่อง

XP เกิดเมื่อ mastery ถูกใช้ในเรื่องที่มีความเสี่ยงและผลขยับ—not when a player repeats a safe action. หาก Step สูงกว่า, งานง่ายไม่ให้ practice. จงเขียนให้รู้สึกว่า “โลกไม่สอนอะไรใหม่จากสิ่งเดิม” แทนการตำหนิผู้เล่น.

> ตัวอย่าง note ที่ดี: “ครั้งนี้เจ้าทำสิ่งที่มือคุ้นอยู่แล้วได้อย่างสะอาด ไม่มีรอยใหม่ให้วิชานี้จดจำ—แต่คนเฝ้าด่านจำใบหน้าของเจ้าได้.”

### 6.3 เวลาและ Leaf

ฉากสั้นไม่ต้องบังคับข้ามวัน. ให้เวลาเปลี่ยนเมื่อการกระทำใช้แรง งาน เดินทาง การรอข่าว การรักษา หรือสร้างผลกระทบใหญ่. Leaf ใหม่เป็นผลจากหลายวันสะสมหรือการเปลี่ยนสถานที่/ความสัมพันธ์ที่สำคัญ—not a page break after every roll.

### 6.4 อายุ

อายุเพิ่มเมื่อปฏิทินข้ามฤดูเกิดในปีต่อมาเท่านั้น. ไม่ใช้ age เป็น penalty อัตโนมัติในเวอร์ชันแกน แต่ใช้เพื่อเปลี่ยนน้ำหนักของชื่อเสียง บาดแผล ผู้พึ่งพา และความทรงจำ.

## 7. คู่มือการเขียนฉากและร้อยแก้ว

### 7.1 มุมมองและความยาว

ค่าเริ่มต้นคือ **third-person limited** ตามตัวละครผู้เล่น: ผู้เล่ารู้สิ่งที่ตัวละครเห็น ได้ยิน เดา หรือรู้จากหลักฐาน. ห้ามกระโดดเข้าใจความคิดของ NPC แล้วเฉลยแผนลับ เว้นแต่เป็นข้อมูลที่ NPC แสดงออกหรือผู้เล่นได้รับอย่างมีต้นทุน.

หลัง resolve, AI GM ต้องเขียน prose สามย่อหน้า:

1. **Aftermath:** รายละเอียดสัมผัสหรือวัตถุ 1–2 อย่างที่เฉพาะสถานที่และ action.
2. **Human reaction:** NPC ตัดสินใจหรือพูดประโยคที่มีน้ำหนัก; ความสัมพันธ์/สถานะต้องปรากฏ.
3. **Consequence and opening:** สิ่งเปลี่ยนจริงและแรงกดดัน/ทางเลือกเฉพาะหน้าใหม่.

ทุกย่อหน้าควรมีอย่างน้อยสองอย่างจาก การกระทำที่มองเห็น, รายละเอียดสัมผัส, การตีความของตัวละคร, หรือผลที่พาไปข้างหน้า. หลีกเลี่ยงภาพเปรียบที่สวยแต่ไม่บอกสิ่งใด.

### 7.2 ความหนาแน่นของรายละเอียด

| ชั้น | ต้องมี | หลีกเลี่ยง |
|---|---|---|
| สถานที่ | วัตถุ เสียง กลิ่น แสง หรือพื้นผิวที่สัมพันธ์กับ action | หมอก ควัน ลม แบบ generic ทุกฉาก |
| ร่างกาย | แผล มือ ความเหนื่อย การยืน น้ำเสียง | บอกว่า “กลัวมาก” โดยไม่แสดง |
| สังคม | ใครมอง ใครเงียบ ใครถือของ/เอกสาร | NPC แค่ “ตกใจ” โดยไม่มีการตัดสินใจ |
| ผล | ทรัพยากร ทางผ่าน ข้อห้าม พยาน เวลา หรือความสัมพันธ์ | “เรื่องดำเนินต่อ” |

### 7.3 บทสนทนา

บทสนทนาไม่ใช่ที่อธิบาย lore. ทุกคนควรอยากได้บางอย่างที่พูดตรง ๆ ไม่หมด. ในภาษาไทยให้ใช้ “…” สำหรับคำพูด และเปลี่ยนย่อหน้าเมื่อผู้พูดเปลี่ยน. คำพูดหนึ่งบรรทัดที่เฉียบคมดีกว่าคำสั่งสอนหลายบรรทัด.

```text
“ข้าไม่ได้ถามว่าเจ้ารู้หนังสือหรือไม่” ผู้คุมใช้ปลายนิ้วแตะรอยหมึกที่ยังชื้น “ข้าถามว่าใครยอมให้เจ้าถือมันมา”
```

### 7.4 สิ่งต้องห้ามในการเขียน

ห้ามใช้คำ/ประโยคต่อไปนี้ใน prose ปกติ: “เรื่องดำเนินต่อ”, “เสียงคนเถียงเรื่องข้าว” โดยไร้บริบท, “โลกขยับ”, “ผู้เล่น”, “AI”, “เต๋า”, “DN”, “XP”, “credit”, “quest complete”, “พลาดและโลกขยับ”, หรือบทสรุปศีลธรรมที่บอกผู้อ่านว่าควรรู้สึกอย่างไร.

## 8. ระดับภาษาและการแปล

### 8.1 กฎใหญ่

เกมเขียน **ไทยร่วมสมัยที่มีน้ำเสียงพงศาวดาร** และ **English literary but clear**. ไม่ประดิษฐ์ภาษาญี่ปุ่นโบราณ ไม่ใช้คำราชาศัพท์ทุกประโยค และไม่คิดว่า “-dono / -sama” คือทางลัดสู่ความแม่นยำ. งานวิจัยด้านภาษาเน้นว่าภาษาปลายมุโรมาจิอยู่ในช่วงเปลี่ยนผ่านและภาษาเขียน/พูดต่างกันอย่างมีนัยสำคัญ [4].

### 8.2 ระดับภาษาไทยในเกม

| ระดับ | ใช้กับ | สรรพนาม/คำเรียกที่แนะนำ | จังหวะ | ตัวอย่าง |
|---|---|---|---|---|
| **L0: Narration / ผู้เล่า** | บรรยายฉาก | ชื่อตัวละคร, เขา/นางเมื่อจำเป็น | งามแต่ชัด ไม่อวดคำโบราณ | “แสงเย็นขาดลงบนรอยพับของบัญชี” |
| **L1: House / ในบ้าน** | ครอบครัว คนสนิท ผู้ร่วมทุกข์ | ข้า–เจ้า, พี่–น้อง, ชื่อเล่น | ตรง อบอุ่น หรือเจ็บปนกัน | “อย่ากลับมือเปล่าอีกเลย” |
| **L2: Peer / ผู้มีฐานะใกล้กัน** | เพื่อนร่วมงาน พ่อค้า คนเดินทาง | ข้า–เจ้า, ฉัน–ท่านตามบุคลิก | ต่อรอง หยอก หรือวัดเชิง | “ถ้าจะให้ข้าข้ามเรือ ก็พูดราคาให้จบ” |
| **L3: Formal request / ผู้ขอ** | ขอความช่วยเหลือจากคนมีสิทธิ์ | ข้า–ท่าน, ผู้น้อย–ท่าน | สุภาพแต่ไม่ยอมลดตนจนไร้ agency | “ข้าขอให้ท่านฟังเหตุผลก่อนสั่งคนพาเราออกไป” |
| **L4: Official power / อำนาจทางการ** | คำสั่ง เอกสาร ด่าน บ้านใหญ่ | นามตำแหน่ง, “ท่าน”, “ใต้เท้า” เฉพาะบริบท | กระชับ มีเงื่อนไข | “ตามหนังสือฉบับนี้ เรือยังออกไม่ได้” |
| **L5: Oath and rupture / คำสัตย์หรือแตกหัก** | สาบาน ปฏิเสธ ท้าทาย ต่อหน้าพยาน | ข้า, เรา, นามเต็ม, คำเรียกที่ตั้งใจเปลี่ยน | สั้น หนัก มีผล | “ต่อหน้าคนเหล่านี้ ข้าจะไม่มอบชื่อเขาให้เจ้า” |

### 8.3 กฎการเปลี่ยนสรรพนาม

การเปลี่ยนจาก “ท่าน” เป็นชื่อจริง, “เจ้า” เป็น “น้อง”, หรือ “ข้า” เป็น “เรา” ต้องมีเหตุผลใน relation state: ความสนิท การข่ม การอับอาย การออกคำสั่ง การยอมรับ หรือคำสัตย์. ห้ามเปลี่ยนเพียงเพื่อเลี่ยงคำซ้ำ.

### 8.4 ระดับภาษาอังกฤษ

| ระดับ | หลัก | ตัวอย่าง |
|---|---|---|
| Narrative | literary, concrete, modern readable | “Rain darkened the seal before either man touched it.” |
| Familiar | plain but personal | “You came back with the wrong kind of quiet.” |
| Formal | precise, withheld, not pseudo-medieval | “Your name is not on the copy I was given.” |
| Official | declarative and conditional | “The gate remains closed pending a witness.” |
| Oath | short, irreversible | “I will not purchase her life with his.” |

ห้ามใช้ `thou`, `thee`, `verily`, หรือ English archaic เป็น default. ความเก่าของโลกมาจากโครงสร้างอำนาจ วัตถุ และผลของคำ ไม่ใช่คำสะกดประหลาด.

### 8.5 คำญี่ปุ่นและคำเฉพาะ

ใช้ศัพท์ญี่ปุ่นเมื่อมีความหมายเชิงโลกที่ไม่มีคำไทย/อังกฤษแทนตรง ๆ หรือจำเป็นสำหรับความชัด แต่ให้แปลครั้งแรกและอย่าใช้เป็นเครื่องประดับ.

| คำ | ใช้ได้เมื่อ | วิธีแสดง |
|---|---|---|
| `daimyō` | กล่าวถึงผู้ปกครอง/บ้านอำนาจในบริบท | “ไดเมียว (daimyō) ผู้ครองอำนาจในพื้นที่” ครั้งแรก |
| `ikki` | กล่าวถึง league/network ที่เฉพาะ | อธิบายกลุ่มและผลประโยชน์, ไม่แปลเป็น “ชาวนากบฏ” ตายตัว |

## 9. AI GM Narrative Protocol

### 9.1 สิ่งที่ AI ได้รับ

AI รับเฉพาะ context ที่ validate แล้ว: campaign date/location, character, masteries, scene, active mission, social state, recent memories, action, และ roll final. AI **ไม่มีสิทธิ์** เปลี่ยน outcome, XP, time, reward, resource หรือ mission state.

### 9.2 สิ่งที่ AI ต้องคืน

| Field | กฎ |
|---|---|
| `sceneTitle` | สั้น มีวัตถุ/แรงกดดัน ไม่ generic |
| `narration` | 3 ย่อหน้า ตามโครง aftermath → human reaction → consequence |
| `nextChoices` | 3 action ที่เป็นรูปธรรม ต่อเนื่องจากฉาก |
| `memory` | เฉพาะการเปลี่ยนที่ตามรอยได้ ไม่สรุปทุกอย่าง |
| `missionNote` | ชี้ thread/pressure แบบไม่อ้างว่าเควสสำเร็จโดยไม่มี state |
| `historicalFence` | บอกสถานะ fact/context/fiction/evidence gap |

### 9.3 Tone matrix

| Outcome | Tone | จังหวะ |
|---|---|---|
| decisive success | โล่งชั่วคราว แต่มีเงาของสิ่งที่จะถูกทวง | เปิดกว้างแล้วตัดด้วยรายละเอียดเล็กที่น่ากังวล |
| success with cost | ได้มาแต่ไม่สะอาด | ให้คนหนึ่งคนเงียบ/จดจำ/ยื่นเงื่อนไข |
| partial success | ช่องแคบที่ยังเดินได้ | ปิดย่อหน้าด้วยทางเลือกที่ต้องตัดสินใจ |
| failure with consequence | หนัก แต่ไม่ปิดเกม | ทางเดิมพัง, สิ่งใหม่ปรากฏ, agency ยังอยู่ |

### 9.4 Local Trial prose

เมื่อ AI ไม่พร้อม Local Trial ต้องยังเขียนฉากอย่างมีคุณภาพ: สถานที่เฉพาะ, NPC ที่มีความต้องการ, ผลจับต้องได้, และ choice ที่ทำต่อได้. ห้ามให้ fallback กลายเป็นข้อความระบบสั้น ๆ.

## 10. Art Bible: Ledger of Ash

### 10.1 แนวคิดภาพ

Dust & Fire ต้องรู้สึกเหมือน **สมุดบันทึกสงครามที่ยังมีคนใช้อยู่** ไม่ใช่ fantasy parchment, ไม่ใช่ samurai anime, และไม่ใช่ dashboard SaaS ที่เอากระดาษมาวางพื้นหลัง. ทุกหน้าเป็น “เอกสารประเภทหนึ่ง” ซึ่งถูกสัมผัส ใช้ จด แก้ และเก็บไว้โดยคนในโลก.

| คุณลักษณะ | ต้องรู้สึก | หลีกเลี่ยง |
|---|---|---|
| กระดาษ | off-white สงบ มีรอยใช้บางจุด | texture หนักจนอ่านยาก, คราบเลือดสุ่มทั่วหน้า |
| หมึก | navy เกือบดำ มีน้ำหนักของบัญชี/คำสั่ง | สีดำสนิทและ shadow หนักแบบเกมสยอง |
| Vermilion | คำสัตย์ ความเสี่ยง รอยคราบ คำตัดสิน | ใช้เป็น accent ทุกปุ่มหรือ underline ทุก tab |
| Ocher | หนี้ ของมีค่า เสบียง หรือคำเตือน | gold gradient หรือ luxury UI |
| Teal | ยืนยัน ความปลอดภัย ความทรงจำที่เก็บแล้ว | green success แบบ generic |

### 10.2 Palette

| Token | Hex | ความหมาย |
|---|---|---|
| Paper | `#FBFAF6` | พื้นอ่านหลัก |
| Ink Navy | `#102B49` | authority, navigation, body system text |
| Dust Vermilion | `#B52B2F` | action มีราคา, oath, stain, danger |
| Ledger Ochre | `#B9861F` | property, debt, provision, warning |
| Archive Teal | `#176C61` | confirmed record, safe passage, memory |
| Ash Grey | `#7A838E` | secondary notation, old routes |

### 10.3 Typography

| งาน | ภาษาอังกฤษ | ภาษาไทย | ข้อห้าม |
|---|---|---|---|
| System heading / command | Poppins หรือ sans ที่คมและกระชับ | Noto Sans Thai | serif ใหญ่ทุกหน้า |
| Chronicle title / wordmark | serif restrained | Noto Serif Thai | display font หลายตระกูล |
| Long prose | literary serif แบบอ่านง่าย | Noto Serif Thai | tracking กับภาษาไทย |
| Ledger label | uppercase sparingly | ไทยตัวปกติขนาดเล็ก | all caps ภาษาไทย/คำเยอะ |

### 10.4 Global composition

ทุก route สำคัญควรมี **ledger spine**: ตัวตนแคมเปญ, folio/Leaf, เวลา/สถานที่, navigation, และสถานะอ่านอยู่. เนื้อหาหลักเป็น open leaf; context รองเป็น margin note, stamped record, map legend หรือ evidence strip—not a grid of equal cards.

| หน้า | เอกสารที่ควรเลียนแบบ | Motif |
|---|---|---|
| Campaign Command | แผนที่ภาคสนามที่พับได้ | route line, known/unknown edge, seal pin |
| Play | โต๊ะทำการกับแผ่นบันทึกผล | dice tray, intention line, result strip |
| Chronicle | ชั้นใบเรื่องและ leaf ที่เปิดอยู่ | folio number, marginal mark, record stamp |
| Character | dossier ที่แนบเอกสารหลายชั้น | portrait seal, margin tabs, skill ledger |
| Market | สมุดบัญชีท่าเรือ | ruled rows, guarantor mark, price reason |
| Missions | dossier ว่าด้วยแรงกดดัน | issuer line, deadline, reward provenance |
| Agreements | สมุดหนี้และผลประโยชน์ | counterpart, witness, what changed hands |
| Save/Load | กล่องเก็บ leaf | auto/manual marks, stamp and dated slot |
| Admin | war office ledger | restricted seal, audit chronology, operational notices |

### 10.5 ภาพตัวละคร

ภาพตัวละครต้องบอก **งานและบริบท** ก่อนบอกความเท่. เสื้อผ้ามีรอยใช้ เปียกฝน มีเศษเส้นใย ขอบแขนเสื้อที่ใช้ซ้ำ หรือเครื่องมือที่มีเหตุผล. หลีกเลี่ยง armor ที่สะอาดเกินจริง pose superhuman, katana glamour shot, ทรงผม/เครื่องแต่งกายจากยุคอื่น, หรือตราตระกูลจริงที่คัดลอก.

| Persona | ภาษาภาพ | วัตถุประกอบ |
|---|---|---|
| คนส่งสาร | ผ้ากันฝนเก่า รองเท้าสกปรก ไหล่ล้า | สายรัดจดหมาย, เชือก, แผนทาง |
| ช่างปืน | หมึกเขม่า โลหะ น้ำมัน และนิ้วที่มีรอยงาน | คีม ผ้าพัน ชิ้นส่วนลำกล้อง |
| พ่อค้า | ผ้าหลายชั้นที่ใช้เดินทางได้, ไม่หรูเกิน | บัญชี ตราชั่ง ถุงผ้า สำเนาเอกสาร |
| คนวัด/คนกลาง | ความเรียบร้อยที่มีภาระ, ไม่ใช่ภาพนักบวชแฟนตาซี | กระดาษพับ เชือกผูก สายตาระวัง |
| ผู้คุ้มกัน | น้ำหนักอยู่ที่ท่ายืนและการระวัง ไม่ใช่อาวุธใหญ่ | ด้ามอาวุธที่ใช้แล้ว ผ้าพันแผล แผ่นป้ายผ่าน |

### 10.6 ภูมิทัศน์และฉาก

ฉากต้องออกแบบเป็น **พื้นที่ตัดสินใจ**. ที่หนึ่งควรตอบได้ว่าคนเข้าออกตรงไหน ใครเห็นอะไร จุดใดทำให้เสียเวลา อะไรเปียก/พัง/หาย และใครถือสิทธิ์ใช้พื้นที่.

| สถานที่ | สิ่งที่ต้องเห็น | สิ่งที่ไม่ควรทำ |
|---|---|---|
| ท่าเรือ | เชือกเปียก บัญชีเรือ คนยกของ กระแสน้ำ จุดตรวจ | เรือรบ/ภูเขาอลังการทุกครั้ง |
| ด่าน | รอยเกวียน สารตรา รั้วชั่วคราว ผู้คุมเหนื่อย | gate แบบปราสาท fantasy สะอาด |
| เซฟเฮาส์ | ผ้าพันแผล กลิ่นยา เตาเล็ก แผนทางซ่อน | ห้องลับไฮเทค/แสง neon |
| ตลาด | ผ้า กะละมัง เสียงต่อรอง คนมอง และทางแคบ | สินค้านับร้อยแบบ MMO |
| วัด/ศาลเจ้า | บัญชี เครื่องใช้ ที่พัก คนต้องพึ่งพา | สถานที่ศักดิ์สิทธิ์ที่ไม่มีการเมือง |

### 10.7 Prompt framework สำหรับงานอาร์ตต้นฉบับ

```text
[medium] + [document type or scene] + [specific place and season] + [human work] +
[two material details] + [social pressure visible in image] +
Ledger of Ash documentary restraint, original fictional heraldry, no text, no logos
```

**ตัวอย่าง:**

> Original Sengoku-inspired field ledger map on weathered off-white paper, fictional river port in early spring, dashed route lines between checkpoint and safehouse, folded-paper creases, ink-wash foothills, a single vermilion wax seal marking current pressure, understated navy and ochre annotations, documentary tabletop artifact, no people, no legible text, no real clan crest, no copyrighted references.

### 10.8 Negative art list

ไม่ใช้: real clan crest, historical portrait copied from archive, famous character likeness, modern military gear, Edo police imagery as Sengoku default, neon, cyberpunk, overly ornate gold UI, glossy 3D game icon, generic AI parchment with unreadable fake text, blood splatter as decoration, anime schoolface, sexualised costume, หรือ uniform ที่ไม่มีสภาพใช้งาน.

## 12. QA Checklist สำหรับเนื้อเรื่อง ภาษา และอาร์ต

### 12.1 Narrative QA

- ทุกฉากมี person with a want, public pressure และ playable question หรือไม่
- ร้อยแก้วสามย่อหน้ามีวัตถุสัมผัส, human reaction, และ consequence จริงหรือไม่
- NPC ทุกคนมีสิ่งที่เสียได้หรือไม่
- outcome ถูกแปลงเป็นผลเชิงเรื่องโดยไม่พูดศัพท์ระบบหรือไม่
- ความพลาดยังเปิด action ต่อไปได้หรือไม่
- reward มี provenance และคนจดจำหรือไม่

### 12.2 Historical QA

- มีการอ้างชื่อเหตุการณ์ สถานที่ บุคคล ตำแหน่ง หรือพิธีจริงหรือไม่
- ถ้ามี fact card ครอบคลุมปี/ภูมิภาค/claim หรือไม่
- เป็น `fact-supported`, `contextual-play`, `campaign-fiction` หรือ `insufficient-evidence` อย่างไร
- ใช้ status, temple, money, disaster หรือ language แบบเหมารวมหรือไม่

### 12.3 Language QA

- ระดับสรรพนามสะท้อนความสัมพันธ์และเปลี่ยนอย่างมีเหตุผลหรือไม่
- ภาษาไทยลื่นและไม่เป็นราชาศัพท์/คำโบราณยัดเยียดหรือไม่
- English ชัดเจนโดยไม่กลายเป็น pseudo-archaic หรือไม่
- คำญี่ปุ่นได้รับคำอธิบายและไม่ใช้เป็น ornament หรือไม่

### 12.4 Art QA

- ภาพบอกงาน วัตถุ สถานที่ และแรงกดดันก่อนความเท่หรือไม่
- มีตรา/เอกสาร/อาวุธ/เครื่องแต่งกายที่อ้างถึงของจริงหรือ copyrighted reference หรือไม่
- Vermilion มีความหมายเชิง risk/oath/stain จริงหรือใช้เป็น decoration หรือไม่
- หน้าจออ่านเป็น ledger artifact มากกว่า SaaS card grid หรือไม่

## 13. Contract สั้นสำหรับระบบที่เรียกใช้ Bible นี้

### AI GM

1. รับเฉพาะ validated game context และ historical brief.
2. ไม่แก้ roll, XP, rewards, time, mission state หรือ resources.
3. เขียน prose ที่คนธรรมดามี agency และอำนาจทำงานผ่านแรงงาน เอกสาร เส้นทาง และผู้ค้ำ.
4. ระบุ historical status/fence ทุกครั้งเมื่อใช้บริบทจริง.
5. ให้ next choices เป็น action เฉพาะ ไม่ใช่คำถามกว้าง ๆ.

### Backend

1. Validate structured AI response, clamp bonus/DN, timeout 45 seconds.
2. Preserve Local Trial fallback โดยไม่หักเครดิตเมื่อ provider ใช้ไม่ได้.
3. Log provenance ของ state changes สำคัญ.
4. ห้ามอนุญาตให้ AI output bypass deterministic engine.

### Art/UI

1. ใช้ palette, document types และ semantic colors ตามหัวข้อ 10.
2. เก็บ navigation/identity/folio ใน ledger spine.
3. แสดง result mechanic ชัดเจนใน UI แต่ปล่อย prose ให้เป็นนิยาย.
4. ไม่ใช้ reference ที่มีลิขสิทธิ์เป็นภาพผลิตภัณฑ์หรือ prompt สำหรับเลียนแบบ.
