# Dust & Fire: ระบบความชำนาญ เวลา อายุ และภารกิจ

> เอกสารออกแบบฉบับนี้กำหนดให้ทุกความก้าวหน้าเกิดจากสิ่งที่ผู้เล่นทำในฉาก ไม่ใช่จากการกดรับเควสหรือการวนทอยเพื่อสะสมตัวเลข ระบบนี้รักษาแกนเดิมของเกมคือ **ผู้เล่นพูดหนึ่งประโยค เกมตีความความเสี่ยง ทอย 2d12 แล้วโลกเปลี่ยน**

## 1. เป้าหมายของการรีเซ็ตระบบ

Dust & Fire ไม่ควรรู้สึกเหมือนชีวิตจริงที่ทุกวันยืดยาว แต่ก็ไม่ควรเหมือนเกมที่ฉากกระโดดข้ามเวลาอย่างไร้ร่องรอย ความก้าวหน้าจึงต้องบอกผู้เล่นว่า **ตนเก่งขึ้นเพราะผ่านอะไรมา**, **กาลเวลาผ่านไปเพราะเลือกทำอะไร**, และ **ภารกิจคลี่คลายเพราะการกระทำในเรื่องตรงกับเงื่อนไขใด**

การแก้ครั้งนี้มีขอบเขตชัดเจนดังตารางต่อไปนี้

| ระบบ | สิ่งที่ผู้เล่นสัมผัส | สิ่งที่เกมคำนวณเงียบ ๆ | สิ่งที่ไม่ทำ |
|---|---|---|---|
| ความชำนาญ | เห็นระดับ 1–20, XP ปัจจุบัน และขั้นถัดไป | ตัดสินว่าสกิลใดถูกใช้จริงและให้ XP ตามผลกระทบ | ไม่แจก XP จากการทอยซ้ำแบบไม่มีผลต่อฉาก |
| เวลา | เห็นช่วงวันและผลสะสม เช่น “บ่ายล่วงเป็นค่ำ” | เลื่อนช่วงวันหรือปิดวันตามขนาดของผลลัพธ์ | ไม่บังคับว่าทอยหนึ่งครั้งต้องผ่านหนึ่งวัน |
| อายุ | เห็นอายุปัจจุบันใน Dossier และบันทึกเมื่อข้ามปี | เพิ่มอายุเมื่อปฏิทินแคมเปญผ่านวันเกิด | ไม่เพิ่มอายุจากจำนวนครั้งที่ทอย |
| ภารกิจ | เห็นว่ากำลังพาเรื่องไปสู่เป้าหมายใด | ตรวจ trigger ในผลทอยและเปลี่ยนสถานะ/มอบรางวัล | ไม่มีปุ่ม “Accept quest” ที่ตัดขาดจากเรื่อง |
| รางวัล | เห็นสิ่งที่ได้และผลที่ต้องจ่ายในผลฉาก | เพิ่มของ, สิทธิ์, บุญคุณ, ข้อมูล หรือคลายหนี้ | ไม่ใช้เงินสดเป็นรางวัลหลักเสมอไป |

## 2. คำหลัก

| คำใน UI | ความหมายเชิงกลไก | เหตุผลด้านเรื่องเล่า |
|---|---|---|
| **Discipline / วิชาที่ฝึก** | ความชำนาญรายแขนง ระดับ 1–20 | สื่อว่าฝีมือเติบโตจากการผ่านงาน ไม่ใช่ค่าตัวเลขลอย ๆ |
| **Practice / XP** | หน่วยประสบการณ์ของวิชานั้น | เป็นร่องรอยของการใช้งานอย่างมีความเสี่ยง |
| **Step / ขั้น** | ระดับปัจจุบันของวิชา | ใช้แทนคำว่า level เมื่ออยู่บนหน้าฉาก เพื่อลดฟีลเกม MMO |
| **Threshold / ขั้นถัดไป** | XP ที่ต้องใช้เพื่อก้าวขึ้นอีกหนึ่งขั้น | เป็นบันได ไม่ใช่เส้นตรง |
| **Time mark / รอยเวลา** | การขยับของช่วงวัน วัน และฤดูกาล | บอกผลของการกระทำโดยไม่ต้องแจ้งจำนวนชั่วโมงเทียม |
| **Thread / เส้นเรื่องงาน** | ภารกิจที่กำลังดำเนิน | เป็นเป้าหมายของฉาก ไม่ใช่รายการงานที่ผู้เล่นต้องกดรับ |

## 3. สเกลความชำนาญ 1–20

### 3.1 หลักการ

ทุก **Mastery** ที่มีอยู่เดิมจะมี `rank` ตั้งแต่ 1 ถึง 20 และ `xp` ของตนเอง ไม่ใช้เลเวลรวมของตัวละคร เพราะช่างที่เจรจาเก่งขึ้นไม่ควรทำให้ยิงปืนหรืออ่านแผนที่เก่งขึ้นโดยอัตโนมัติ ระดับ 20 คือเพดานของแคมเปญปกติ และแสดงเป็น **Mastered / ถึงขีดสุดของวิชานี้** แทนการวน XP ต่อไป

ตัวเลขโบนัสทอยยังต้องไม่ทำลายสมดุล 2d12 จึงแยก **ระดับที่มองเห็น** ออกจาก **โบนัสที่ใช้ทอย** ดังนี้

| ขั้นที่เห็น | โบนัส Mastery ในการทอย | ความหมายในนิยาย |
|---|---:|---|
| 1–4 | +1 | รู้พื้นฐาน พอทำงานธรรมดาได้ |
| 5–8 | +2 | ทำได้อย่างมั่นคงในงานที่คุ้น |
| 9–12 | +3 | เป็นคนที่ผู้อื่นเริ่มนึกถึงเมื่อมีงานนี้ |
| 13–16 | +4 | มืออาชีพที่รับมือแรงกดดันเฉพาะทางได้ |
| 17–19 | +5 | ฝีมือสูง มีชื่อหรือมีวิธีของตนเอง |
| 20 | +5 และได้ “Mastery Mark” เชิงเรื่อง | ถึงขีดสุด โบนัสไม่โตต่อ แต่เรื่องตอบสนองต่อชื่อเสียง/ลายมือ/วิธีการ |

> **ข้อสำคัญ:** ขั้น 20 ไม่ทำให้ผลทอยไร้ความเสี่ยง เพราะความยากยังมาจากสถานการณ์ อำนาจ ความลับ เวลา แผล และผลประโยชน์ของคนอื่น

### 3.2 การย้ายเซฟเดิม

Mastery เดิมที่ให้โบนัส `+1`, `+2`, `+3`, `+4`, `+5` จะถูกย้ายอย่างปลอดภัยไปที่ขั้น `4`, `8`, `12`, `16`, `20` ตามลำดับ ดังนั้นพลังในการทอยเดิมไม่ลดลงเมื่อเปิดเซฟเก่า แต่ผู้เล่นจะเห็นทางเติบโตต่อจากตำแหน่งที่เหมาะสม

ตัวอย่างเช่น `Seal work +3` เดิมจะกลายเป็น `Seal work · Step 12 · 0/10 Practice` และยังให้โบนัส +3 เหมือนเดิม จนกว่าจะฝึกเพิ่มถึงขั้น 13

### 3.3 บันได XP

ผู้ใช้เสนอ “ใช้ราวห้าครั้งแล้วขึ้น” ซึ่งเหมาะมากสำหรับช่วงเริ่มต้น จึงใช้ **5 XP ต่อหนึ่งขั้น** ในระดับ 1–4 แล้วเพิ่มเป็นขั้นบันไดที่มองเห็นได้ชัด ไม่เพิ่มแบบเส้นตรงจนน่าเบื่อ

| ช่วงขั้นปัจจุบัน | XP เพื่อก้าวหนึ่งขั้น | เหตุผล | XP สะสมเมื่อเข้าสู่ช่วงแรก |
|---|---:|---|---:|
| 1–4 | 5 | ให้ผู้เล่นรับรู้ความก้าวหน้าภายในประมาณห้าการใช้งานที่มีความหมาย | 0 |
| 5–8 | 7 | ความคุ้นเคยเริ่มต้องการสถานการณ์ใหม่ | 20 |
| 9–12 | 10 | เข้าสู่ระดับที่ตัดสินงานสำคัญได้ | 48 |
| 13–16 | 14 | ต้องเผชิญงานยาก ผลลัพธ์จริง และข้อจำกัดทางสังคม | 88 |
| 17–19 | 18 | การขัดเกลาฝีมือขั้นสูงไม่เกิดจากงานเดิมซ้ำ ๆ | 144 |
| 20 | 0 | ถึงเพดาน | 198 |

ดังนั้น หากเริ่มที่ขั้น 1 จะใช้ **198 XP** ถึงขั้น 20 แต่ตัวละครตัวอย่างที่มี bonus เดิม +3 จะเริ่มที่ขั้น 12 และต้องใช้เพียง 70 XP เพื่อไปถึงขั้น 20 โดยคงความสามารถเดิมทุกอย่าง

### 3.4 กติกาให้ XP

XP ไม่ได้มาจาก “ผ่าน” อย่างเดียว ความล้มเหลวที่เปลี่ยนโลกก็เป็นการเรียนรู้ แต่การทำซ้ำฉากเดิมเพื่อฟาร์มจะไม่ได้แต้ม

| เหตุการณ์หลังทอย | XP วิชาที่ใช้ | เงื่อนไข |
|---|---:|---|
| ใช้วิชาในสถานการณ์ที่มีความเสี่ยงและผลเปลี่ยน | +1 | ได้ทั้งสำเร็จ สำเร็จมีต้นทุน หรือพลาดแต่โลกขยับ |
| วิธีใช้วิชาเป็นหัวใจของผลลัพธ์ | +1 เพิ่ม | เช่น ใช้ Seal work ทำให้เอกสารผ่านด่าน หรือใช้ Street bargaining ลดหนี้จริง |
| ปิดจุดสำคัญของเส้นเรื่องงาน | +1 เพิ่มให้วิชาหลักหนึ่งวิชา | ไม่เกินเพดาน +2 XP ต่อการทอยหนึ่งครั้ง |
| ทอยซ้ำโดยไม่มีข้อมูลใหม่ ความเสี่ยงใหม่ หรือผลใหม่ | 0 | ระบบแสดง “ไม่มีสิ่งใหม่ให้ฝึกจากครั้งนี้” อย่างสุภาพ |
| วิชาถึงขั้น 20 | 0 XP | เปลี่ยนเป็น Mastery Mark เชิงเรื่องแทน |

กฎนี้ทำให้ช่วงขั้น 1–4 เติบโตจากการใช้วิชาที่มีผลราวห้าครั้งตามข้อเสนอของผู้ใช้ ขณะที่ช่วงสูงต้องใช้ทั้งการใช้งานต่อเนื่องและการเผชิญสถานการณ์ที่ต่างออกไป จึงเป็นขั้นบันไดที่สนุกกว่าการเพิ่มเลขแบบคงที่

## 4. เวลาและอายุ: โลกเดินโดยรอยผล ไม่ใช่นาฬิกาเทียม

### 4.1 แคมเปญมีเวลา แต่ไม่บังคับฉากสั้น

เวลามีสามชั้นคือ **ช่วงวัน**, **วันในแคมเปญ**, และ **ฤดูกาล/ปี**. ฉากสนทนาสั้นอาจไม่เลื่อนเวลาเลย การติดตามคน การเดินทาง การรักษาแผล การรอข่าว หรือการตัดสินใจที่เปลี่ยนสมดุลของพื้นที่จะสร้าง `time mark` มากกว่า

| ลักษณะผล | การเปลี่ยนเวลา | ตัวอย่างข้อความที่ผู้เล่นเห็น |
|---|---|---|
| การตอบโต้ทันทีในที่เดิม | ไม่เลื่อน | “คำตอบนี้ยังอยู่ในลมหายใจเดียวกัน” |
| ค้นหา, ต่อรองนาน, เฝ้าดู, เตรียมของ | เลื่อนช่วงวันหนึ่งครั้ง | “บทสนทนายืดไปจนแสงบนกำแพงเปลี่ยนสี” |
| เดินทาง, ซ่อมของ, ซ่อนตัว, ผลใหญ่เปลี่ยนฉาก | ปิดวันหรือเปิดวันใหม่ | “เมื่อกลับมามองฟ้าอีกครั้ง วันเก่าก็หมดลงแล้ว” |
| ผลรวมของเวลาเป็นหลายวัน | สร้าง Leaf ใหม่โดยอัตโนมัติ | “เรื่องนี้เกินกว่าจะเป็นเพียงวันเดียว” |

ระบบจะไม่กำหนดตายตัวว่า “ครบสี่วันต้องเปลี่ยน Leaf” แต่เมื่อรอยเวลาสะสมเป็นหลายวัน โดยทั่วไป **ราว 4–5 วัน** หรือเมื่อเหตุการณ์เปลี่ยนสถานที่/ความสัมพันธ์อย่างมีนัยสำคัญ เกมจะปิด `Leaf` เดิมและเปิด Leaf ใหม่ เพื่อให้ผู้เล่นรู้สึกว่าเรื่องก้าวไปเป็นช่วง ไม่ใช่ชีวิตประจำวันที่ถูกเร่งจนไร้น้ำหนัก

### 4.2 อายุ

อายุเป็นคุณสมบัติของตัวละคร มี `ageAtCampaignStart`, `campaignStartYear` และ `birthSeason` (ไม่จำเป็นต้องเปิดเผยวันเกิดละเอียด) ระบบคำนวณอายุจากปีและฤดูกาลของแคมเปญ:

1. อายุ **ไม่เพิ่มจากการทอย** และไม่เพิ่มจากการข้ามวันธรรมดา
2. เมื่อปีแคมเปญผ่านปีเริ่มต้นและข้ามฤดูกาลเกิด ระบบเพิ่มอายุหนึ่งปีและเขียนบันทึกสั้นใน Chronicle
3. การข้ามเวลาหลายวันหรือหลายเดือนเพราะเรื่องเล่าต้องเป็นผลที่ผู้เล่นเข้าใจได้ เช่น เดินทาง ฟื้นตัว หลบหนี หรือรับใช้กองทัพ ไม่ใช่การเร่งเวลาเพื่อให้แก่เร็ว
4. Age update เปิดโอกาสให้ GM เปลี่ยนน้ำหนักของชื่อเสียง ความสัมพันธ์ บาดแผล และภาระ แต่ไม่ลดค่าสกิลอัตโนมัติในเวอร์ชันแรก

## 5. ภารกิจ: ไม่มีปุ่มรับงาน แต่อยู่ในทุกผลลัพธ์

หน้า Missions จะเป็น **Mission Dossier** แบบอ่านอย่างเดียว ผู้เล่นรู้ว่าเรื่องใดกำลังกดดันอยู่, ใครรออะไร, เงื่อนไขสำเร็จโดยนัยคืออะไร, และผลที่อาจต้องจ่าย แต่ไม่มีปุ่ม Accept, Continue หรือ Complete

ทุก mission จะมี `progressTriggers` ที่ระบบใช้ตีความหลังการทอย เช่น `secure-safe-passage`, `protect-echiya`, `obtain-firearms`, `settle-debt`. ใน Local Trial trigger มาจาก outcome tag และสกิล/วิธีที่ใช้; ใน AI mode GM เสนอ mission update ที่ถูกตรวจด้วย allowlist เดิมก่อนเกมยอมรับ

| สถานะ | สิ่งที่เห็นหน้า Missions | สิ่งที่เกิดในฉาก |
|---|---|---|
| Offered | บริบทและผู้เกี่ยวข้อง | เกมเริ่มติดตามเมื่อผู้เล่นพูดหรือทำสิ่งที่แตะเส้นเรื่องนั้น |
| Active | ความกดดัน เส้นตาย และสิ่งที่ยังไม่ชัด | ทุกผลทอยอาจเพิ่ม ลด หรือเบนความคืบหน้า |
| Resolved | รายการถูกย้ายไป Chronicle พร้อมผลลัพธ์ | ของ/สิทธิ์/บุญคุณ/ข้อมูลถูกเพิ่มตามรางวัลบริบท |
| Lost / Changed | บันทึกเหตุผลว่าพลาดหรือเปลี่ยนรูป | โลกอาจเสนอเส้นเรื่องใหม่แทน ไม่ลบหลักฐานเดิม |

รางวัลเป็นทรัพยากรตามชนชั้นและผู้ให้ภารกิจ: อาจเป็นสัมภาระ, การเข้าไปในสถานที่, การค้ำประกัน, การลดหนี้, คนช่วย, ข่าว, หรือชื่อที่คนยอมฟัง. เงินสดใช้ได้แต่ไม่ใช่รางวัลมาตรฐานของทุกงาน

## 6. สมุดสัญญาและผลประโยชน์

คำว่า **Exchange History** ทำให้ดูเหมือนใบเสร็จซื้อขาย แต่สิ่งที่หน้าเดิมเก็บจริงกว้างกว่า: การแลกของ การชำระหนี้ การรับบุญคุณ การให้คำมั่น และผู้ที่เห็นเหตุการณ์ จึงเปลี่ยนชื่อเป็น:

| ภาษา | ชื่อใหม่ | คำอธิบายสั้น |
|---|---|---|
| English | **Agreements & Consequences** | What changed hands, who remembers, and what is still owed. |
| ไทย | **สมุดสัญญาและผลประโยชน์** | ของ คำมั่น หนี้ และคนที่จดจำการแลกเปลี่ยนนี้ |

แต่ละรายการจะแสดงเพียงสี่คำถาม: **ใครเกี่ยวข้อง**, **อะไรเปลี่ยนมือ**, **สิ่งใดต้องจ่าย**, และ **ผลนี้เปิด/ปิดทางใด**. ภารกิจที่สำเร็จอัตโนมัติจะเขียนรายการหนึ่งบรรทัดที่นี่เชื่อมไปหา Chronicle ได้

## 7. Save Game และ Load Game

`Campaign Safekeeping` เป็นชื่อกว้างเกินและทำให้ดูเหมือนมีระบบเซฟอีกชั้น จึงจะยุบออกจากเมนู. ทางเข้าที่เหลือมีเพียง:

| เมนู | ทำอะไร | สิ่งที่ไม่ทำ |
|---|---|---|
| **Save Game / บันทึกเกม** | สร้างหรือเขียนทับ Manual Leaf ของ Local Save | ไม่สร้างแคมเปญหรือคลังเซฟแยก |
| **Load Game / โหลดเกม** | คืน Auto Save หรือ Manual Leaf สู่แคมเปญที่เปิดอยู่ | ไม่แก้ Chronicle เดิมและไม่ส่งข้อมูลขึ้นเซิร์ฟเวอร์ |

Auto Save ยังมีอยู่ แต่เป็นคุณสมบัติของ Save Game เท่านั้น ไม่ใช่เมนูแคมเปญใหม่

## 8. หน้า Play หลังปรับ

หน้า Play ยังคงเป็นฉากเดียว ไม่เปิดหน้าผลทอยใหม่. หลังผู้เล่นกดยืนยันเจตนา ระบบแสดงการทอยแบบมีจังหวะบนกระดาษฉากเดิม และเมื่อทอยจบ กล่องผลจะขยายในตำแหน่งเดิมก่อน prose ต่อเนื่อง

### 8.1 ข้อมูลก่อนทอย

เหนือ narrative มี **Skill Ledger** ขนาดกะทัดรัด แสดงวิชาที่ผู้เล่นมีอยู่พร้อมขั้นและ XP. เมื่อระบบวิเคราะห์เจตนาแล้ว แถววิชาที่ใช้จะเด่นขึ้น เช่น:

> **Seal work · Step 12** — `7 / 10 Practice` · โบนัสปัจจุบัน `+3` · ขั้นถัดไป: *known for the work*

ระบบไม่เฉลยวิชาที่จะใช้ในโหมด “ดูความเสี่ยง” ตามกติกาเดิม แต่เมื่อผู้เล่นยืนยันเจตนาแล้วจึงเปิดให้เห็นอย่างโปร่งใส

### 8.2 จังหวะการทอย

การทอยใช้ animation สั้น กระชับ และหยุดได้ตาม `prefers-reduced-motion`:

1. ผู้เล่นกด **Roll 2d12**.
2. ลูกเต๋าในถาดเปลี่ยนหน้าราว 600–800ms พร้อมข้อความ `The room holds its breath / ทั้งห้องกลั้นลมหายใจ`.
3. ตัวเลขหยุด พร้อม `total / DN` และระดับผล `clear success`, `success with cost`, `setback`, หรือผลที่ระบบเดิมกำหนด.
4. กล่องเดียวกันเปิดแถบ **Skill Practice**, **Time Mark**, และ **Story Result**.
5. เมื่อผู้เล่นบันทึกผล prose ยาวและผลภารกิจถูกแสดงในฉากเดิม ไม่กระโดดไปหน้าใหม่

### 8.3 กล่องผลหลังทอย

| ชั้นในกล่องผล | ข้อมูลที่ต้องเห็น | ตัวอย่าง |
|---|---|---|
| ผลทอย | 2d12, total, DN, ระดับผล | `5 + 4 = 9 / DN 10 · setback` |
| วิชาที่ฝึก | ชื่อวิชา, ขั้น, XP ที่ได้, progress ขั้นถัดไป | `Seal work +2 Practice · 9/10` |
| รอยเวลา | เวลาเลื่อนหรือไม่ และเหตุผลเชิงเรื่อง | `บทสนทนายืดถึงยามเย็น` |
| เส้นเรื่องงาน | คืบหน้า/สำเร็จ/เปลี่ยนรูป | `Echiya’s safety: 2/2 · resolved` |
| รางวัล | ของ, สิทธิ์, ข่าว, บุญคุณ หรือหนี้ที่เปลี่ยน | `ได้รับ: จดหมายผ่านด่านหนึ่งฉบับ` |
| ร้อยแก้ว | ผลเล่าเรื่องหลายย่อหน้า | ยังอยู่ในกล่องฉากเดียวและอ่านต่อจากผลทอยได้ |

## 9. โครงข้อมูลที่เพิ่ม

```ts
type SkillProgress = {
  rank: number;       // 1..20
  xp: number;         // 0..xpNeeded(rank)-1, 0 at rank 20
  totalXp: number;    // audit/readable history
  masteryMark?: string;
};

type CampaignClock = {
  day: number;
  segment: "dawn" | "day" | "dusk" | "night";
  timeMarksSinceLeaf: number;
  daysSinceLeaf: number;
};

type CharacterAge = {
  ageAtCampaignStart: number;
  campaignStartYear: number;
  birthSeason: Season;
  currentAge: number;
};

type MissionProgress = {
  triggerId: string;
  current: number;
  required: number;
  resolvedBy?: string;
  rewardGranted?: boolean;
};
```

การ migration ต้องสร้างข้อมูลนี้สำหรับ Local Save เดิมโดยไม่ทำให้ rolls, items, debts, save leaves, Chronicle หรือความสามารถเดิมหายไป

## 10. เกณฑ์ตรวจรับก่อนเปิดให้ลอง

| กรณี | ผลที่ต้องยืนยัน |
|---|---|
| ใช้ Mastery เดิม +3 | ย้ายเป็น Step 12 และยังให้โบนัส +3 |
| ทำการใช้วิชามีความหมายห้าครั้งช่วงขั้น 1–4 | ได้ครบ 5 XP และเลื่อนขั้นหนึ่งครั้ง |
| ทอยซ้ำโดยไม่มีผลเปลี่ยน | ไม่ได้ XP ซ้ำ |
| สำเร็จงานด้วย trigger ที่ตรง | Mission เปลี่ยนเป็น Resolved, ได้รางวัล, เขียนสมุดสัญญา |
| ทอยในฉากสั้น | เวลาไม่จำเป็นต้องเลื่อน |
| ทำงานยืดเยื้อ | มี Time Mark และเมื่อหลายวันสะสมจะเปิด Leaf ใหม่ |
| ปฏิทินข้ามวันเกิด | อายุเพิ่มหนึ่งและ Chronicle มีบรรทัดบันทึก |
| เปิดเซฟเก่า | migration ทำงานโดย Local Save เดิมยังโหลดได้ |
| reduce motion | ผลทอยข้าม animation แต่ยังเห็นตัวเลขและผลครบ |

## 11. ข้อเสนอที่นำไปทำในรอบแรก

รอบแรกจะเริ่มจาก Local Trial และ state ในเบราว์เซอร์ก่อน เพื่อให้ผู้ใช้ลองวงจรเต็มได้ทันที. AI GM จะยังถูกคุมด้วย schema เดิม; เมื่อพร้อม จะส่งกลับเพียง `skillUsed`, `xpAward`, `timeMark` และ `missionUpdate` ที่ผ่าน allowlist เท่านั้น. ไม่มีการปล่อยให้โมเดลสร้างรางวัล XP หรือข้ามเวลาตามอำเภอใจ

ลำดับการพัฒนาคือ: เพิ่ม model/migration → เขียน test curve และผลทอย → แสดง Skill Ledger/animation/result block ใน Play → แปลง Missions เป็น dossier → เปลี่ยนชื่อสมุดสัญญา → ยุบ Safekeeping เป็น Save/Load → capture ทั้งวงจรให้ผู้ใช้ตรวจ
