# Dust & Fire — แบบรับ Feedback สำหรับรอบถัดไป

เอกสารนี้ทำไว้เพื่อให้การชี้แก้ครั้งถัดไปเปลี่ยนเป็นงานที่ตรวจรับได้ทันที โดยไม่ต้องอธิบายระบบทั้งชุดซ้ำ ผู้ใช้เลือกตอบเฉพาะหัวข้อที่ต้องการได้ และหนึ่งข้อความสั้นต่อหัวข้อเพียงพอ

## 1. เลือกหน้าผู้เล่นกลุ่มถัดไป

| ตัวเลือก | หน้าที่จะตรวจและปรับ | คำถามที่ต้องตัดสินใจ |
|---|---|---|
| A. New Campaign | ขั้นสร้างตัวละครและสรุปก่อนเริ่ม | การเปิดเรื่องควรสั้นลงหรือให้ถามความสัมพันธ์มากขึ้นหรือไม่ |
| B. Prepare | Character, Market, Gear, Services, Debts | ข้อมูลใดควรอยู่ใน viewport แรกเสมอ |
| C. Chronicle | Library, Reader Mode, World Archive | การอ่านเรื่องควรเน้นใบล่าสุดหรือค้นย้อนหลังมากกว่า |
| D. Save / Load | manual save, auto save และแคมเปญในเครื่อง | คำอธิบายใดทำให้ความต่างของ Leaf / Auto / Manual ยังงง |

## 2. รูปแบบ feedback ของ UI

ใช้รูปแบบต่อไปนี้ได้เลย:

> **หน้า:** `ชื่อหน้า`  
> **ตำแหน่ง:** `ส่วนบน / กลาง / ล่าง / ปุ่ม / ข้อความ`  
> **ปัญหา:** `สิ่งที่อ่านแล้วงง หรือสิ่งที่ไม่ควรมี`  
> **อยากได้:** `ตัวอย่างคำ/โครง/อารมณ์ที่อยากเห็น`

ตัวอย่าง:

> **หน้า:** Prepare → Character  
> **ตำแหน่ง:** ด้านบน  
> **ปัญหา:** เห็น XP ก่อนแล้วไม่รู้ว่าเรื่องกำลังทำอะไร  
> **อยากได้:** ให้ภารกิจปัจจุบันขึ้นก่อน XP

## 3. เอกสารที่รอความเห็น

| ชุดเอกสาร | จุดที่ควรให้ความเห็น | ทางเลือกที่ต้องการคำตอบ |
|---|---|---|
| เอกสารกลางและคู่มือ 7 ทีม | ขอบเขต MVP, Local Save, AI fallback | จะคง Local Save เป็นหลักต่อ หรือวางแผนบัญชี/Cloud Save ต่อเลย |
| กติกาและสรุปตัวละคร | ภาษาไทยของค่าสถานะและตัวอย่างทอย | มีคำใดที่ยังไม่เข้าบรรยากาศหรือไม่ |
| Lore / Narrative / Art Bible | โทนความมืด การเมือง และระดับภาษา | ให้เพิ่มหรือลดความโหด ความเศร้า หรือรายละเอียดประวัติศาสตร์ตรงใด |
| รายงาน 7 ทีม | ลำดับความสำคัญรอบหน้า | เลือก 1–2 ทีมที่จะให้เป็นแกนรอบถัดไป |

## 4. ข้อมูลที่ไม่ต้องตอบซ้ำ

ระบบปัจจุบันคงหลักการต่อไปนี้ไว้แล้ว: ผู้เล่นเขียนเจตนาเอง, เกมทอย 2d12, Local Save อยู่ในเบราว์เซอร์, แผนที่ไม่เดาอำนาจการปกครอง, และข้อมูลประวัติศาสตร์ที่ไม่มีแหล่งอ้างอิงจะไม่ถูกเติมเป็นข้อเท็จจริง
