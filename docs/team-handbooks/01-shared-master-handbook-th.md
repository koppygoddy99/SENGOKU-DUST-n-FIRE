# Dust & Fire: Sengoku Stories — เอกสารกลางสำหรับทุกทีม

## สถานะและหน้าที่ของเอกสาร

เอกสารนี้เป็นเอกสารกลางแบบตัวอักษรล้วนของ **Dust & Fire: Sengoku Stories** ใช้ร่วมกันโดย Game Director, Game Design, Game Development, UI/UX Frontend, Art and Audio, QA and Testing และ Release and Operations จุดประสงค์ของเอกสารคือทำให้ทุกทีมตอบคำถามเดียวกันได้ตรงกันว่าเกมนี้คืออะไร ผู้เล่นควรรู้สึกอย่างไร ระบบใดเป็นของจริง อะไรคือขอบเขตของความสมจริงทางประวัติศาสตร์ และเมื่อมีการเปลี่ยนแปลงใดบ้างที่ต้องได้รับการอนุมัติก่อนลงมือ

เอกสารนี้ไม่ใช่คู่มือปุ่มหรือโค้ดรายไฟล์ รายละเอียด implementation ที่มีผลต่อ state transition ให้ยึด `docs/dust-fire-core-game-source-of-truth-th.md` เป็น canonical source เสมอ รายละเอียดโทนการเขียน ภาษา และ art direction ให้ยึด `docs/dust-fire-lore-narrative-art-bible-th.md` ประกอบ หากเอกสารฉบับใดขัดกับสองฉบับดังกล่าว ให้หยุดตีความเองและเปิดประเด็นตัดสินใจตามกระบวนการในหัวข้อสุดท้าย

> แก่นของ Dust & Fire คือ “คนธรรมดาหรือผู้มีอำนาจระดับเล็กต้องเลือกทางเดินในโลกที่ชื่อเสียง เอกสาร หนี้ เสบียง ข่าวลือ และความรุนแรงมีราคาเท่ากัน” ผู้เล่นไม่ถูกขอให้เล่นเป็นตัวเลข แต่ถูกขอให้รับผิดชอบต่อประโยคที่ตนพูดและรอยที่ประโยคนั้นทิ้งไว้

## 1. วิสัยทัศน์ของผลิตภัณฑ์

Dust & Fire เป็นเกม tabletop role-playing เชิงนิยายประวัติศาสตร์ต้นฉบับที่เล่นในเบราว์เซอร์ เกมตั้งอยู่ใน “บริบท” ของญี่ปุ่นยุคเซ็นโกกุ แต่ไม่ได้อ้างว่า NPC สมมติ เหตุการณ์ย่อย หรือฉากภายในเกมเป็นข้อเท็จจริงทางประวัติศาสตร์ เว้นแต่มี fact card และแหล่งอ้างอิงรองรับอย่างชัดเจน เกมให้ความสำคัญกับแรงกดดันของสังคมสงคราม—เส้นทางค้า การเกณฑ์แรงงาน เอกสารรับรอง บ้านใหญ่ ชุมชน วัด คนเรือ ผู้คุม และเครือญาติ—มากกว่าการเลียนแบบเรื่องราวของตัวละครจริง

ประสบการณ์ที่ต้องส่งมอบมีสามชั้นพร้อมกัน ชั้นแรกคือความเป็นนิยาย: ผู้เล่นอ่านฉากที่มีสถานที่ ประสาทสัมผัส บทสนทนา และสิ่งที่เสี่ยงจะสูญเสีย ชั้นที่สองคือความเป็น tabletop: ผู้เล่นเลือกเจตนา ทอย 2d12 เห็นผลและตัดสินใจว่าจะใช้ Momentum หรือไม่ ชั้นที่สามคือความเป็นบัญชีสงคราม: โลกจำสัญญา หนี้ รอยแผล ชื่อเสียง ของที่เปลี่ยนมือ และเวลาที่ผ่านไป

| คำมั่นสัญญา | ความหมายในประสบการณ์ผู้เล่น | ผลต่อทีมพัฒนา |
|---|---|---|
| หนึ่งประโยคก่อนระบบ | ผู้เล่นพูดสิ่งที่ตัวละครทำโดยไม่ต้องเลือก stat หรือสกิล | UI และ AI ต้องไม่ผลักภาระคำนวณไปยังผู้เล่น |
| ผลต้องทิ้งรอย | ต่อให้สำเร็จก็มีพยาน สัญญา ข่าว หรือภาระที่ติดตามได้ | ทุก state mutation ต้องสร้าง provenance ที่ตรวจได้ |
| ประวัติศาสตร์เป็นขอบเขต | โลกสมจริงโดยไม่อวดอ้างเกินหลักฐาน | เนื้อหาและ AI ต้องใช้ Historical Fence ทุกครั้งที่จำเป็น |
| เล่นต่อได้แม้ AI ล้ม | ความต่อเนื่องของแคมเปญสำคัญกว่า provider | Local Trial และ Local Save เป็น capability หลัก ไม่ใช่ fallback ที่ถูกซ่อน |
| ความชำนาญเติบโตจากความเสี่ยง | การใช้วิชาที่มีน้ำหนักสร้าง Step ไม่ใช่การฟาร์ม | XP, DN threshold และ mission trigger ต้องเดินร่วมกัน |

## 2. กลุ่มผู้เล่นและกรอบ MVP

ผู้เล่นหลักคือคนที่ชอบ role-play เชิงเนื้อเรื่อง การเมืองระดับชุมชน ความขัดแย้งของสถานะ และความสมจริงที่มีขอบเขต ไม่จำเป็นต้องรู้ประวัติศาสตร์ญี่ปุ่นลึกก่อนเล่น แต่ต้องสามารถสัมผัสได้ว่าโลกมีระเบียบทางสังคมและผลของการตัดสินใจ ผู้เล่นรองคือคนที่ชอบเกมทอยเต๋าแบบเข้าใจง่ายและอยากเห็นตัวละครมีประวัติการเติบโตต่อเนื่อง

MVP ของเกมไม่ใช่ open world ประวัติศาสตร์ทั้งญี่ปุ่น และไม่ใช่ quest graph หลายร้อยเส้น สิ่งที่ต้องทำให้แน่นคือ vertical slice หนึ่งแคมเปญที่เริ่มฉาก เลือกเจตนา ทอย รับผล รับ XP เดินเวลา ขยับภารกิจ รับรางวัลที่มีที่มา บันทึกใน Chronicle และกลับมาเล่นต่อจาก Local Save ได้

| อยู่ใน MVP ที่ต้องทำให้แน่น | อยู่ในข้อมูล/vertical slice | ยังไม่ควรอ้างว่าเสร็จ |
|---|---|---|
| Intent → analyze → 2d12 → consequence | ภารกิจอัตโนมัติหนึ่งเส้นหรือไม่กี่เส้น | mission graph หลายแคว้นเต็มรูปแบบ |
| Mastery Step 1–20 และ XP staircase | ข้อตกลง/รางวัลตามฐานะผู้มอบ | ระบบเศรษฐกิจจำลองสมบูรณ์ |
| เวลา อายุ และ Leaf หลายวัน | ตลาดและบริการเชิง context | การสึกหรอ/บริโภค/รักษาเต็ม loop |
| AI GM พร้อม Local Trial fallback | historical fact cards ที่คัดมา | ฐานประวัติศาสตร์ครบทุกปีทุกแคว้น |
| Local Save, Chronicle, Character Dossier | Admin Console สำหรับ oversight | ระบบ live operations ขนาดใหญ่ |

## 3. Canonical play loop

วงจรต่อไปนี้คือแกนที่ทุกหน้า ทุกบริการ และทุกข้อความต้องเคารพ ผู้เล่นอาจเห็นเพียงส่วนหนึ่งใน UI แต่ state transition ต้องเดินครบตามลำดับ

```text
Declare Intent
  → Assess / Analyze risk
  → Confirm intent
  → Deterministic 2d12
  → Optional Momentum
  → Resolve consequence
  → Practice, Step, time, age, mission, reward
  → Chronicle, Agreement, Memory
  → Auto Save
  → next playable scene
```

การประกาศเจตนาต้องเป็นประโยคเดียวที่มีอย่างน้อยเป้าหมาย วิธี หรือความเสี่ยงที่อ่านได้ เช่น “ข้าจะยื่นบัญชีข้าวต่อหน้าผู้คุมเพื่อซื้อเวลาให้ชาวบ้านเก็บเกี่ยว” ระบบสามารถวิเคราะห์ว่าหลักฐาน เอกสาร สถานะ และพยานเกี่ยวข้องอย่างไร แต่ห้ามบังคับให้ผู้เล่นเลือก `Mind`, `Accounting` หรือ DN ด้วยตนเอง

สูตรทอย canonical คือ `d12 + d12 + axis + mastery bonus + context bonus + momentum bonus` โดย axis มีห้าแกน: **Prowess / พละกำลัง**, **Craft / ฝีมือ**, **Instinct / ไหวพริบ**, **Judgment / ปัญญา** และ **Resolve / พลังใจ** Context bonus อยู่ระหว่าง 0 ถึง +2 ส่วน Momentum ให้ +2 หลังเห็นผลทอยและมีได้เมื่อค่าไม่เป็นศูนย์ ผลทอยถูกตัดสินโดย deterministic engine เท่านั้น AI GM ไม่มีสิทธิ์แก้ total, margin หรือ outcome

| Margin | Outcome | คำมั่นสัญญาเชิงเรื่อง |
|---:|---|---|
| ตั้งแต่ +5 | Decisive success | เปิดทางชัด แต่โลกยังจำว่าใครช่วยและใครเสียหน้า |
| 0 ถึง +4 | Success with cost | ผู้เล่นได้สิ่งที่ทำ แต่ต้องรับพยาน หนี้ ข่าว หรือเงื่อนไข |
| -4 ถึง -1 | Partial success | ได้ทางเลือก เวลา หรือข้อมูลบางส่วน โดยแรงกดดันยังอยู่ |
| ไม่เกิน -5 | Failure with consequence | ทางเดิมพัง แต่เกมต้องเปิดทางอื่นผ่านต้นทุน รอยด่าง หรือสถานะใหม่ |

## 4. ตัวละคร ความชำนาญ และความก้าวหน้า

ตัวละครไม่ได้มี “เลเวลรวม” ที่ทำให้ทุกด้านเก่งขึ้นพร้อมกัน ความชำนาญเป็นรายวิชา เช่น งานเรือ การต่อรอง เอกสาร ดินปืน งานช่าง เครือญาติ หรือความรู้เส้นทาง ผู้เล่นจึงอาจเป็นคนที่น่าเชื่อถือเรื่องน้ำและเรือ แต่ยังเสียเปรียบในการพูดต่อหน้าผู้มีฐานะสูง

Step มีตั้งแต่ 1 ถึง 20 และแบ่งเป็นบันไดห้าช่วง ช่วงแรกเติบโตจากการใช้วิชาที่สร้างผลจริงราวห้าครั้ง แต่ช่วงสูงต้องเผชิญ DN ที่หนักขึ้นจึงได้ XP ขั้นสูงสุดคือ Step 20 ซึ่งไม่รับ XP ต่อและเปลี่ยนเป็น **Mastery Mark** เชิงเรื่อง เช่น ผู้คนเริ่มเรียกชื่อวิชานั้นของตัวละคร มีผู้มาขอความช่วยเหลือ หรือศัตรูเตรียมรับมือเป็นการเฉพาะ

| Step | ช่วงชื่อ | โบนัส | DN ขั้นต่ำเพื่อรับ XP | ความหมายในการเขียนฉาก |
|---:|---|---:|---:|---|
| 1–4 | มือเริ่มมั่น | +1 | 10 | ตัวละครทำได้ แต่ยังต้องพิสูจน์เมื่อมีพยาน |
| 5–8 | ชำนาญใช้งาน | +2 | 10 | คนใกล้ตัวเริ่มฝากงานและคาดหวังผล |
| 9–12 | คนเริ่มนึกถึง | +3 | 14 | ชื่อเริ่มเดินทางเร็วกว่าตัวละคร |
| 13–16 | ฝีมือผ่านแรงกดดัน | +4 | 18 | วิชาถูกทดสอบต่อหน้าอำนาจหรือความเสี่ยงจริง |
| 17–19 | ฝีมือมีชื่อ | +5 | 22 | การใช้วิชาเปลี่ยนดุลของฉากและดึงความสนใจ |
| 20 | ถึงขีดสุด | +5 | ไม่รับ XP | โลกตอบสนองด้วยชื่อ ภาระ และมรดกของวิชา |

XP ไม่ควรมาจากการกดทอยซ้ำโดยไม่มีความเสี่ยงหรือผลใหม่ การใช้วิชาที่ทำให้โลกขยับได้ +1 XP และได้อีก +1 เมื่อวิชานั้นเป็นหัวใจของวิธีการ รวมต่อ roll ไม่เกิน 2 หาก DN ต่ำกว่า threshold ของ Step ปัจจุบัน ให้แสดงว่า “งานนี้ยังไม่หนักพอที่จะขัดเกลาวิชาขั้นนี้” แทนการแจก XP ปลอม

## 5. เวลา อายุ Leaf และจังหวะของเรื่อง

เกมต้องไม่ตัดวันหลังทุกการทอย เพราะจะทำให้เรื่องรู้สึกเร่งและไม่มีพื้นที่ให้คนอยู่กับผลของคำพูด การตอบโต้ทันทีอาจไม่เดินเวลา การต่อรอง เฝ้าดู เตรียมของ หรือค้นหาข้อมูลอาจใช้หนึ่ง time mark การเดินทาง งานซ่อม หลบซ่อน หรือผลที่ทำให้แผนเปลี่ยนอาจใช้สอง time marks หรือปิดวัน เมื่อเวลาสะสมผ่านสี่วันจึงเปิด Leaf ใหม่

Leaf คือหน่วยการเล่าเรื่อง ไม่ใช่ tick ของระบบ เมื่อ Leaf ใหม่เปิด Chronicle ต้องทำให้ผู้เล่นรู้ว่าอะไรเปลี่ยนไปในช่วงหลายวันนั้น เช่น ฝนทำให้เส้นทางเสีย ผู้คุมเปลี่ยนเวร ราคาข้าวขึ้น ข่าวเดินถึงตลาด หรือใครเริ่มถามหาชื่อตัวละคร อายุเพิ่มเมื่อปฏิทินข้ามฤดูเกิดในปีถัดไปเท่านั้น ไม่เพิ่มตามจำนวน roll, จำนวน Leaf หรือจำนวนครั้งที่ผู้เล่นเปิดหน้าเกม

## 6. Mission Thread, รางวัล และสมุดสัญญา

ภารกิจเป็นเส้นเรื่องที่เกิดจากสถานการณ์ ไม่ใช่รายการ checkbox ผู้เล่นไม่กดรับหรือกดส่งงาน หน้า Missions จึงเป็น **Mission Dossier** ที่บอกว่าใครกำลังรออะไร เส้นตายคืออะไร ความเสี่ยงต่อใคร และรางวัลจะมีลักษณะเช่นใด ระบบตรวจว่า action และ outcome แตะ trigger ของภารกิจหรือไม่ แล้วเพิ่ม progress, เปลี่ยน state หรือ resolve เอง

เมื่อภารกิจคลี่คลาย รางวัลต้องเข้ากับฐานะผู้มอบ ชาวบ้านให้เสบียง ที่พัก แรงงาน หรือคำค้ำชุมชน; พ่อค้าให้เครดิต ข่าว เส้นทาง หรือสินค้า; ซามูไรหรือบ้านใหญ่ให้ใบผ่าน คำรับรอง หรือสิทธิ์เข้าถึง; วัดอาจให้คนกลางหรือที่พักพิง รางวัลเงินสดไม่ใช่ default เพราะทำให้โครงสร้างอำนาจของโลกแบนลง

ทุก reward หรือการแลกเปลี่ยนสำคัญต้องลงใน **Agreements & Consequences / สมุดสัญญาและผลประโยชน์** ซึ่งตอบสี่คำถามเสมอ: ใครเกี่ยวข้อง, สิ่งใดเปลี่ยนมือ, ใครเป็นพยาน, และผลนี้เปิดหรือปิดทางใด ชื่อเดิม “Exchange History” จึงไม่ควรกลับมาใช้ เพราะไม่ได้อธิบายสิ่งที่ผู้เล่นต้องตัดสินใจ

## 7. เนื้อเรื่อง ภาษา และขอบเขตประวัติศาสตร์

โทนเรื่องต้องสงบ แต่ไม่อ่อนแอ; สวยได้ แต่ไม่กลบความสกปรกของอำนาจ; รุนแรงได้ แต่ไม่ยกความรุนแรงเป็นเครื่องประดับ ทุกฉากควรเริ่มจากสิ่งที่จับต้องได้—อากาศ กลิ่นไม้ ชามข้าว เชือก ขอบเอกสาร รองเท้าดินเปียก เสียงประตู หรือวิธีที่คนหลบสายตา—ก่อนจึงเข้าสู่ความขัดแย้งทางอำนาจ ผู้เล่นควรเห็นว่าคนต่ำกว่าอำนาจต้องระวังคำพูดอย่างไร และคนมีอำนาจเองก็มีหนี้ต่อชื่อ บ้าน และผู้ใต้บังคับบัญชาอย่างไร

ระดับภาษาไทยแบ่งตามระยะทางทางสังคม ไม่ใช่การทำให้ทุกคนพูดโบราณแบบเดียว ชาวบ้านหรือคนใกล้ชิดพูดตรงและมีคำเรียกสั้น ผู้ใต้บังคับบัญชาพูดระวังตัว คนของบ้านใหญ่ใช้ถ้อยคำที่มีพื้นที่ปฏิเสธได้ ผู้มีอำนาจระดับสูงไม่ต้องใช้ราชาศัพท์เสมอไป แต่ต้องพูดให้เห็นว่าคำของตนทำให้คนอื่นเสียหรือได้อะไร ภาษาอังกฤษของ UI ใช้คำสั่งสั้น ชัด และร่วมสมัย เช่น `Declare Intent`, `Save Game`, `Current Leaf`; ภาษาไทยรองใช้ความหมายที่กระชับ ไม่แปลตรงตัวจนแข็ง

Historical Fence มีสี่ระดับ: `fact-supported` เมื่อมีหลักฐานตรง, `contextual-play` เมื่อใช้ข้อเท็จจริงเชิงโครงสร้างกำกับฉากสมมติ, `campaign-fiction` เมื่อเป็นองค์ประกอบแคมเปญที่แต่งขึ้น, และ `insufficient-evidence` เมื่อไม่มีหลักฐานพอสำหรับคำกล่าวเฉพาะ AI GM ต้องยอมรับความไม่รู้แทนการสร้างคำตอบปลอม

## 8. AI GM, Local Trial และความรับผิดชอบของระบบ

AI GM มีหน้าที่วิเคราะห์ intent, เสนอ axis/mastery/difficulty/contextual risk, เขียนฉากผลลัพธ์อย่างน้อยสามย่อหน้า, สร้าง choices ถัดไป และแสดง Historical Fence AI ไม่ใช่เจ้าของกติกา ไม่ทอยเต๋า ไม่แก้ outcome ไม่แจกของ และไม่เขียน state mutation แบบที่ deterministic engine ตรวจไม่ได้

เมื่อ AI timeout, provider ตอบผิด, เครดิตไม่พอ หรือแอปอยู่ UI preview mode เกมต้องเปลี่ยนเป็น **Local Trial** อย่างซื่อสัตย์ Local Trial ใช้กติกา 2d12 เดียวกัน บันทึกผลใน Local Save เดียวกัน และต้องไม่หักเครดิตหรืออ้างว่า AI เป็นผู้ตัดสิน ผู้เล่นต้องยังเล่นต่อได้โดยไม่สูญเสีย continuity

## 9. สัญญาข้ามทีม

| การเปลี่ยนแปลง | ต้องมีเจ้าของ | ต้องได้รับการตรวจจาก |
|---|---|---|
| สูตรทอย, Step, XP, DN, time mark หรือ reward | Game Design | Game Development, QA, Game Director |
| schema, migration, Local Save, AI contract หรือ role guard | Game Development | QA, Release and Operations |
| ลำดับหน้า, CTA, disclosure, accessibility หรือ responsive UI | UI/UX Frontend | Game Design, QA |
| prose, NPC, fact card, language register หรือ historical fence | Game Director | Game Design, Art and Audio |
| ฟอนต์ สี asset, sound cue หรือ motion | Art and Audio | UI/UX Frontend, Game Director |
| test matrix, difficulty gate หรือ bug severity | QA and Testing | ทีมเจ้าของระบบ |
| release, monitoring, incident หรือ privacy | Release and Operations | Game Development, QA |

การเปลี่ยนแปลงใดที่ทำให้ผู้เล่นได้หรือเสียทรัพยากร สำเร็จภารกิจ เปลี่ยน Step เดินเวลา หรือเปลี่ยนชื่อเสียง ต้องมี test และ state provenance หากเปลี่ยนคำหรือภาพที่สร้างความหมายทางสถานะ ต้องมี language/art review หากเปลี่ยนแหล่งข้อเท็จจริงประวัติศาสตร์ ต้องบันทึก source และ Historical Fence

## 10. Definition of Done กลาง

งานหนึ่งชิ้นถือว่าเสร็จเมื่อมีครบสี่ชั้น: ชั้นประสบการณ์ ผู้เล่นเข้าใจว่าทำอะไรและอะไรเปลี่ยน; ชั้น state ทุกการเปลี่ยนมีที่มาและ Local Save กลับมาได้; ชั้นคุณภาพ มี test ที่ป้องกัน regression และตรวจ desktop/mobile ตามความเสี่ยง; ชั้นปฏิบัติการ มีข้อความ error/fallback ที่ไม่หลอกผู้เล่นและสามารถติดตามปัญหาได้

งานไม่เสร็จเพียงเพราะ UI แสดงได้ หรือเพราะ unit test หนึ่งตัวผ่าน หากเป็นกติกาใหม่ต้องทดสอบ migration, edge case และ Local Trial หากเป็นเนื้อหาใหม่ต้องทดสอบภาษา สถานะประวัติศาสตร์ และผลต่อ agency หากเป็นหน้าใหม่ต้องทดสอบเส้นทางออก การเข้าถึงด้วยคีย์บอร์ด และ overflow ใน viewport สำคัญ
